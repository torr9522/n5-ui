## RC Acceptance

Both source mode and package mode installed from GitHub-hosted `v0.3.0-rc1`
assets. Package mode installed the frozen AArch64 panel and Custom Xray. The
runtime updater was forced through the GitHub RC download branch and selected
`Xray-linux-arm64.zip`. No ARM flow fetched an AMD64 N5 asset.

External tests passed for VMess TCP, VLESS TCP, Legacy Shadowsocks TCP, Trojan
TCP, and Legacy Shadowsocks UDP DNS. The VMess client enabled mux and made
multiple requests. Access logs retained the correct `[inbound-<port>]` marker,
including the mux path. The Access IP parser, DB, API, and browser page recorded
the external source. An API-created N5 freedom egress and traffic-policy binding
proved the generated routing path on a real request.

The RC package installation survived a real OS reboot. The boot ID changed;
panel/Xray hashes, DB, service enablement, port-limit timer/table, protocol
listeners, external TCP/UDP, Access IP, routing, and browser UAT all passed
after reboot. Journal blocker count was zero.

## Stable Official Install

After Stable publication, the RC installation was product-uninstalled and all
N5-owned leftovers were checked absent. The following exact public command ran
successfully on the clean Debian 12 ARM64 target:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/torr9522/n5-ui/main/install.sh)
```

Source mode cloned public `main` at the release code commit and downloaded
`releases/latest/download/Xray-linux-arm64.zip`. Its native panel, runtime,
service, DB, config, port-limit, external TCP, inbound tag, and Access IP smoke
passed. Its N5 AMD64 asset fetch count was zero.

The source install was then product-uninstalled and clean state was verified.
`INSTALL_MODE=package` with the same public raw installer downloaded the public
Stable `x-ui-linux-arm64.tar.gz`. The installed panel, Xray, and embedded runtime
ZIP matched the frozen Stable hashes. No AMD64 N5 asset was fetched.

## Stable External And Reboot Acceptance

On the official package installation, API-created VMess, VLESS, Legacy
Shadowsocks, and Trojan inbounds passed external TCP. Legacy Shadowsocks passed
external UDP DNS. VMess mux, N5 routing, inbound tags, Access IP, Browser UAT,
DB integrity/foreign keys, Xray config, systemd, and port-limit passed.

The default updater, with no release-base override and with the embedded ZIP
temporarily moved aside, downloaded from GitHub `releases/latest/download` and
installed the expected ARM64 Xray SHA. The embedded payload was then restored
byte-for-byte.

A second real OS reboot validated the official Stable package installation.
The boot ID changed and all hashes, services, DB/config, external TCP, external
UDP, Access IP, routing, and browser tests passed again. The full boot journal
and N5 service journal produced zero blocker matches.

Temporary UAT inbounds, policy, egress, binding, and Access IP records were
removed through product APIs. Final DB integrity and foreign-key checks passed,
the final Xray config validated, and the Stable package-mode service remains
active and enabled.

## Browser And Database Results

Browser UAT passed login, N5 branding, inbounds, Access IP, traffic policy,
egress, and settings pages with no page errors, failed requests, HTTP 5xx, or
functional console error. Chromium emitted one generic missing-favicon 404
console message; it did not correspond to a failed functional request.

`PRAGMA integrity_check` returned `ok` throughout. `PRAGMA foreign_key_check`
returned zero rows. No DB schema, routing semantics, API semantics, or UI
semantics were changed for ARM support.

## Problems Encountered During Final Release

1. GitHub would not dispatch a workflow absent from the default branch. The
   workflow gained a PR trigger and PR #1 provided a native AMD64 run.
2. Debian-container Git rejected the mounted workspace ownership. The workflow
   added the exact workspace to `safe.directory`; the native build passed.
3. A PR checkout initially built GitHub's synthetic merge revision. Checkout
   was pinned to the PR head SHA and VCS metadata then matched release code.
4. The native ARM builder lacked `rsync`. It was installed inside the isolated
   Debian 11 builder; no host runtime substitution was made.
5. A local QEMU AMD64 probe hit a QEMU internal SIGSEGV. It was not accepted as
   evidence; the native GitHub AMD64 runner supplied authoritative results.
6. Xray's legacy Shadowsocks outbound client did not return a reply against the
   test inbound. Standard `shadowsocks-libev` 3.3.5 passed both TCP and UDP
   against the same API-created server inbound.
7. A routing harness treated valid JSON boolean `false` as a `jq -e` failure.
   Extraction was changed to preserve the boolean value; routing passed.
8. A dual-stack HTTPS hostname intermittently resolved to an unreachable IPv6
   path on the target. Direct IPv4 worked. Protocol tests used Cloudflare's
   certificate-valid IPv4 endpoint so the proxy path, not host IPv6 health,
   determined the result.
9. Package mode retained an embedded ARM runtime ZIP, which correctly short-
   circuited remote updater download. The ZIP was temporarily moved, the updater
   downloaded from GitHub and passed, and the exact embedded bytes were restored.
10. `git diff --check` reports whitespace inside the canonical patch payload.
    The patch bytes are provenance evidence with a fixed SHA. Actual repository
    changes pass when that literal patch payload is excluded; clean apply and
    reconstructed-tree equality remain authoritative for the patch.
11. The installed `gh` client did not expose an `isLatest` JSON field. GitHub's
    official Releases API confirmed `v0.3.0` as latest.
12. A shell fetch-audit counter returned an empty value for zero matches. The
    harness switched to line counting; source and package AMD64 fetch counts
    remained zero.
