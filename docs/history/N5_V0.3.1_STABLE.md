## Fixes

1. VLESS + REALITY browser share export now uses the first trim-non-empty
   `serverNames` entry, matching URL, Base64, Clash, and Mihomo backend output.
2. A historical or restored N5 traffic-policy binding that references a
   missing inbound no longer aborts Xray configuration generation. Only
   `gorm.ErrRecordNotFound` from that lookup is warned and skipped; other
   database failures still fail generation.
3. Inbound deletion continues to remove its traffic-policy bindings in the
   same transaction, preventing new orphan relationships.

The exact historical origin of the reported orphan rows remains unknown.
History proves that code before cleanup commit `93e2616` could leave a binding
when an inbound was deleted, but there is no evidence that this was the path
that produced the reported database.

## Problems Encountered

1. The fresh image lacked `curl`; CA certificates and curl were installed as
   bootstrap prerequisites before running the unchanged public installer.
2. SSH initially refused connections while the reinstall finished. The new
   host key was recorded in a task-specific known-hosts file once SSH opened.
3. The first REALITY fixture incorrectly included the client-only VLESS
   `encryption` field in server settings. Xray rejected it before startup; the
   fixture was corrected to the server schema and all product tests passed.
4. Two shell assertions mishandled nested SQLite JSON quoting and quoted Clash
   YAML. They changed no product source; SQL files and a standard-library export
   parser replaced those harness steps.
5. One plain HTTP endpoint returned an empty response during the Legacy
   Shadowsocks smoke. A certificate-valid Cloudflare HTTPS request through the
   same listener passed immediately.
